# VSCode Logs Monitor

This Python script monitors the log files generated by Visual Studio Code and sends their content to a syslog server. It uses the `watchdog` library to track changes in log files and the `rich` library for styled console output.

## Features

- Monitors `.log` files in the Visual Studio Code logs directory.
- Sends log messages to a syslog server.
- Displays log messages in the console with styled output based on severity levels.
- Handles file creation, modification, deletion, and movement events.
- Supports traceback handling using the `ctraceback` library.
- Automatically scans existing `.log` files in the target directory upon startup.

## Requirements

- Python 3.6 or higher
- Libraries:
  - `watchdog`
  - `rich`
  - `ctraceback`
  - `pydebugger`
  - `configset`

## Installation

1. Clone this repository or copy the script to your local machine.
2. Install the required Python libraries:
   ```sh
   pip install watchdog rich ctraceback pydebugger configset
   ```

## Configuration

The script uses the following configuration variables, which are loaded from an `.ini` file located in the same directory as the script:

- `LOG_DIR`: The directory where Visual Studio Code logs are stored. By default, it points to `%APPDATA%\Code\logs` on Windows.
- `SYSLOG_SERVER`: The IP address of the syslog server. Default is `127.0.0.1`.
- `SYSLOG_PORT`: The port of the syslog server. Default is `514`.
- `HOSTNAME`: The hostname to include in syslog messages. Default is the system's hostname or `127.0.0.1`.

You can modify these variables in the `.ini` configuration file or directly in the script.

## Usage

1. Run the script:
   ```sh
   python vsclogs.py
   ```
2. The script will:
   - Scan the existing `.log` files in the `LOG_DIR` directory.
   - Start monitoring the directory for new or modified `.log` files.
   - Send log messages to the configured syslog server.

## Log Levels

The script parses log levels from the log messages and applies styles for console output. Supported log levels include:

- `info`
- `debug`
- `error`
- `warning`
- `notice`
- `alert`
- `emergency`
- `critical`

## File Event Handling

The script handles the following file events:

- **Created**: Starts monitoring new `.log` files.
- **Modified**: Monitors changes to `.log` files if they are not already being tailed.
- **Deleted**: Removes deleted files from the tracking list.
- **Moved**: Updates the tracking list for moved files.

## Example Output

When a log message is detected, it is sent to the syslog server and displayed in the console with appropriate styling based on its severity level.

## Error Handling

- If a file cannot be accessed or read, an error message is displayed in the console, and the error is sent to the syslog server.
- The script uses `ctraceback` to provide detailed traceback information for unhandled exceptions.
